## Live deployment

- **URL:** https://shadow-hunt-theta.vercel.app. This is a Vercel Services project (`web` + `game` container), built from `main`.
- **Verified against production:** `/api/health` responds, two clients join one room over `wss://…/api/…`, and a headless browser joined by invite link and started a bot match with no page errors.
- **Measured limitation:** a Vercel WebSocket is closed about 300 s after it opens (Hobby). The client reconnects immediately, but Vercel routes it to a different instance, and the room lives only in the original instance's memory, so the player is out of the room. Full matches therefore can't finish on Vercel Hobby. The fix is to host the game server on an always-on service (option B in docs/DEPLOYMENT.md) and keep Vercel for the web app.
- **First build failed:** pnpm tried to clone `uWebSockets.js` over SSH, pulled in by the `colyseus` meta-package. The fix was to depend on `@colyseus/core` directly.

## Known limitations / honest gaps

1. **Characters** are procedural articulated rigs, not skinned glTF models. They have real joint hierarchies and pose-driven animation for every required state. The `Rig` interface in `apps/web/src/game/characters/rig.ts` is where production models plug in.
2. **Audio** is original, procedurally synthesized WAV generated by `apps/web/scripts/gen-audio.mjs`. It is placeholder quality. It is not compressed (about 3.8 MB).
3. **Wallhack at the data level.** All positions replicate to all clients. Fog and occlusion hide survivors visually, but a modified client could read them. The planned fix is Colyseus `StateView` interest management.
4. **Not tested against a live Supabase project.** No credentials were available. The Supabase store, Google and email sign-in paths are implemented and type-checked. The file store path is what the tests ran.
5. **Vercel Services config added (`vercel.json`): `web` (Vite) + `game` (container), all game traffic under `/api`.** Verified locally: a rehearsal of the Dockerfile stages, the production server on port 80, and the production web bundle behind a Vercel-style router (invite join and a match). Known Vercel constraints: WebSockets close at the function max duration (5 min on Hobby) and the client reconnects to the same seat; rooms are per instance. Not deployed yet. Earlier note: Vercel, Railway, Render and Fly configs are written. The Docker image was not built because no Docker daemon was available. The equivalent pruned production install (`pnpm deploy --prod`) plus the bundle was started and passed its health check.
6. **Mobile** was verified in an emulated landscape iPhone viewport with touch enabled in headless Chrome. It was not tested on physical iOS or Android hardware.
7. **Performance** was observed only under software rendering. Frame-rate targets (60 desktop / 30 mobile) are unmeasured on real GPUs.
8. **No jumping.** Maps are single-level, and basements or bunkers are reached by stairs and hatches.
9. **Single process.** One server process holds all rooms. Horizontal scaling needs Redis presence and a driver.
